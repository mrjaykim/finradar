# ADR-010: 학습 데이터셋 설계 - 기업-분기 패널과 Prediction Window

## 상태
결정됨 (2026-08-10)

## 배경
단순히 "상장폐지 기업=1, 정상 기업=0"으로 라벨링하면 조기경보 시스템의 취지에 맞지
않는다. 같은 기업도 시점에 따라 재무상태가 다르므로, 라벨은 기업 단위가 아니라
기업-분기 단위로 부여해야 한다.

## 선택
1. **모집단**: 2010년 이후 KOSPI/KOSDAQ/KONEX 상장기업. 실측 결과 2010년 컷오프 시
   실질부실 표본 756건 보존 확인, 2015년 컷오프는 452건으로 급감해 기각 (ADR-008/009
   후속으로 확보한 mart.delisted_company ⋈ mart.company 조인 결과 기준, 2026-08-10
   세션에서 SELECT로 검증)
2. **ML 문제 정의**: "기업의 현재+과거 재무정보로 향후 N분기(prediction window) 내
   distress(실질부실 상장폐지) 발생 가능성을 예측"
3. **Positive 라벨**: 실질부실 상장폐지 사건 직전 N분기 재무제표에 라벨=1
4. **Negative 정의**: 관측 시점 이후 prediction window 내에 distress가 발생하지 않은
   기업-분기 (단순히 "현재 살아있는 기업의 아무 시점"이 아님 - data leakage 방지)
5. **Negative 샘플링**: 시장(코스피/코스닥/코넥스) 비율 층화, Positive 대비 약 1:3 목표
6. **Prediction window(N)**: 4분기(1년)를 기본값으로 시작, 4주차 모델링 단계에서 여러
   값(4/8분기 등)을 실험적으로 비교
7. **최종 산출물**: 분류 확률을 0~100 Risk Score로 변환 (분류를 대체하지 않고 그 위에
   얹음)

## 트레이드오프
- 756건은 최종 학습 샘플 수가 아니라 Positive 사건 후보군이다. 실제 샘플 수는 각
  기업의 가용 재무제표 분기 수에 따라 달라진다 (이후 재무제표 수집 시 확정)
- industry_code가 없어 업종 층화는 불가능하고, 시장 구분만으로 대체한다 (한계로 남김 -
  mart.company의 industry_code는 corpCode.xml에 없는 정보라 현재 전부 NULL, ADR-009
  참고)
- 1:3 비율은 "실제 부실 확률"이 아니라 "학습 데이터 구성 비율"일 뿐임을 명시한다

## 추가 결정 (2026-08-13): 재무제표 수집 범위

### 배경 - DART API의 2015년 데이터 제공 제약
DART OpenAPI 재무제표 API(`fnlttSinglAcntAll`/`fnlttSinglAcnt`)는 공식 문서상
**사업연도 2015년 이후만 데이터를 제공**한다("2015년 이후부터 정보제공"). 756건의
실제 `delisted_on`에 "상장폐지 시점 기준 과거 8분기"를 대입해 실제 가용 분기 수를
실측한 결과:

| 확보 가능 분기 수 (2015Q1 바닥 기준) | 기업 수 | 비율 |
|---|---|---|
| 8분기 (요청대로 전부) | 389 | 51.5% |
| 4~7분기 (일부만) | 23 | 3.0% |
| 1~3분기 (거의 없음) | 26 | 3.4% |
| 0분기 (전혀 없음) | 318 | 42.1% |

0분기 가용 318건은 2015년 1분기 이전(또는 그 시점 부근)에 이미 상장폐지된
기업들로, 대부분 2010~2014년 폐지 케이스(304건)와 2015년 초 폐지 일부다.

### 결정
1. **0분기 가용 318건은 이번 수집 대상에서 제외한다.** 재무 피처가 전혀 없어
   현재 설계로는 학습에 쓸 수 없다.
2. **4~7분기만 가용한 23건은 일단 수집한다.** 4주차 window 실험(N=4/8분기 비교)
   단계에서 해당 실험의 최소 요구 분기 수에 못 미치면 그때 걸러낸다. 즉 필터링
   시점을 수집 단계가 아니라 모델링 단계로 미룬다.
3. **부실기업(756건 중 0분기 제외 대상) 수집 구간**: `delisted_on` 기준 과거 최대
   12분기, 단 2015-01-01 하한. 12분기는 N=8 window 실험 + 피처 엔지니어링(YoY/QoQ
   변화율 등)용 4분기 여유분을 더한 값이며, 2015년 API 바닥 제약이 실제 상한선으로
   작용한다.
4. **정상기업(약 2,268건, 756×3 목표) 수집 구간**: 2015-01-01~현재 중 기업당 최대
   12분기. 단순히 "최근 분기"로 고정하지 않고, Positive 사건의 연도별 분포에 맞춰
   시점을 층화 샘플링한다 - 그렇지 않으면 모델이 진짜 리스크 신호 대신 "오래된
   스냅샷=위험, 최근=안전" 같은 시간 아티팩트를 학습할 위험이 있다.

## 추가 결정 (2026-08-13): industry_code 원시값 확보

### 전제 정정
트레이드오프 항목의 "industry_code가 없어 업종 층화는 불가능하다"는 표현은 부정확했다.
실제로는 corpCode.xml 벌크 적재 파이프라인(`load_mart_company.py`)에 업종 필드가 없었을
뿐이고, DART OpenAPI의 기업개황(`company.json`) 엔드포인트는 `induty_code`(업종코드)를
제공한다(`crtfc_key`+`corp_code` 단건 조회, 배치 불가). 일일 호출 한도(10,000회) 대비
회사 1개당 1콜의 비용은 크지 않다(대상 3,660건 기준 약 37%).

### 결정
1. `mart.company.industry_code`에 `company.json`의 `induty_code` 원시값을 그대로 채운다
   (`scripts/backfill_company_industry_code.py`). 대상은 is_active=true 전체 상장사
   (2,904건) + 2010년 이후 실질부실 상장폐지 기업(756건 후보군) = 3,660건이며,
   `raw.dart_company_overview`에 원본 응답을 적재한 뒤 mart를 갱신한다.
2. "정상기업 후보"를 ADR-010 항목 5의 1:3 목표치(756×3=2,268)가 아니라 is_active=true
   전체(2,904건)로 잡았다 - 층화 샘플링 로직 자체가 아직 4주차 미구현 작업이라, 지금
   목록을 확정하는 대신 전체를 미리 확보해 4주차에 어떤 샘플링 방식을 쓰든 추가 API
   호출 없이 진행할 수 있게 하기 위함이다.
3. `induty_code`는 KSIC 세분류 수준 원시코드라 그 자체로는 층화 그룹으로 쓰기 어렵다.
   대분류/중분류 매핑과 실제 층화 샘플링 설계는 계속 4주차 모델링 단계로 보류한다.
